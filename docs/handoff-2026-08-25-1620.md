## Decisions (the why, not just the what)

**Phase 3 merged in THREE stages, not one (ruling P3-R3).** My original two-stage ruling was wrong and
the final review caught it: Stage A bundled the read-switch with the additive migration, so deploying
it would have made all 8 brands read Program columns that were still NULL — a silent public content
regression, made worse by a 1-hour cache TTL. Correct order, executed:
  - **A1** additive columns/endpoints/copiers/scripts → deploy → *verified public output unchanged*
  - dump + both backfills `--apply` → **purge caches** → verify
  - **A2** consumer repointing + read switch + admin UI → deploy → verify
  - **B** the column drop → deploy → verify → metadata strip

**The cache purge after the backfill is non-negotiable.** The backfill writes through a raw Prisma
client with ZERO cache invalidation, while every other writer of those fields invalidates at ~10
sites. `diff-landing-payloads.ts` reads *through* those caches — so verifying before purging would
compare two stale responses and could green-light the irreversible drop on bad evidence.

**Active-program resolver is shared, with a fallback (P3-R1).** Two of 8 brands (Vietnam, Korea) match
nothing under `isPublished && isActive`. Fixing only the backfill would have written their data where
the reader never looks. One module, rule 1 unchanged and first, rule 2 falls back by
`year DESC, createdAt DESC, id ASC`. Proven against prod: 8/8 resolve, 0 skips.
`get-auth-context.handler.ts` deliberately still uses the old predicate — different question, own
known bug. **Do not repoint it.**

**Registration dates display the SPAN, not the current window.** Admins extend by appending validity
periods (10–22 per tier in prod), so the UI was showing the last one-day extension. Display now uses
MIN(start)→MAX(end); eligibility/payment gating still uses per-period logic.

**Datetimes: storage was already right.** 278 `timestamptz` columns, prod on UTC, global
`TransformInterceptor` emits ISO UTC. Only display was wrong. Viewer-local via `useHydrated()` +
`<LocalDateTime>`; SSR emits **labelled WIB**, not the server's UTC, so no-JS readers and crawlers get
a correctly-attributed time.

**Agenda shows BOTH WIB and viewer time** — WIB authoritative (physical Indonesian events must match a
printed schedule), viewer's day appended only when it genuinely differs.

## Traps that cost real time this session — do not relearn

- **`npm run lint` in `services/api` is `eslint --fix`. It MUTATES the tree.** Use
  `npx eslint <paths>` to measure. It silently rewrote 3 unrelated spec files in two checkouts.
- **There are TWO tsconfigs.** `tsc --noEmit -p tsconfig.json` does NOT cover `prisma/seeds/**`
  (that's `tsconfig.seed.json`). This is what failed the first Stage B deploy — 17 lines in 4 seed
  files still wrote dropped columns. **Add `npm run build:seed` to your gate set.**
- **A clean merge is not a working merge.** Phase 2's merged tree didn't compile (a new dependency
  wasn't installed in the target checkout); the admin build failed on a stale `.next`. Always verify
  the merged result *before* pushing.
- **`npx jest | tail` returns tail's exit code, not jest's.** Read the `Test Suites:` line.
- **A regression proof only counts if the file still compiles.** An injection that breaks parsing
  makes jest collect 0 tests, which proves nothing. Confirm the test count is unchanged.
- **Commit the fix BEFORE injecting to prove it** — `git checkout --` discards uncommitted work.
- **Never `git stash` in a shared worktree**; a foreign stash lives on that stack.
- **Comparing row counts across time requires the SAME predicate**, or you measure the query, not the
  data (I "lost" a timeline row this way; it was my own missing `deleted_at IS NULL`).
- **Verify mojibake by hex-encoding bytes, never `chr()` on glyphs** — `chr(128)` is U+0080, not €.
- Prod DB: container `ybb-platform-api-yeghdi-postgres-api-1`, db `ybb_platform_db`, user
  `ybb_api_user`. Redis is `ybb-platform-redis-service-omv9vw` (several redis containers share the
  host). Dokploy's checkout needs `git -c safe.directory=...` (root-owned).
- **Deploy latency is minutes.** Watch a *semantic* signal (a B-only file in `dist`, or the schema
  itself), never container uptime — I misread A1's restart as A2's.

## The recurring defect class — 12 instances across this work

*A value is silently lost because one layer does not carry what the layer beside it writes. A guard at
one layer does not protect the layer above it.*

Latest instances: the exception filter dropping every `code` (#7); `contactItemSchema` missing the
VarChar caps the DTO had (#10); the seed files outside the main tsconfig (#12). **When you add a
guard, ask which layer it does NOT cover.**
