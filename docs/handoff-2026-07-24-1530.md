## The original incident

China Youth Summit 2026 Invitation Letters reached participants with every `{{token}}` unsubstituted,
while the admin preview rendered perfectly. Reported by admin Aldi. Three independent root causes:

1. **`placeholders` shredded on save.** `create-update-program-content.dto.ts` declared
   `placeholders?: Array<{key,label,source}>` with no `@Type()`. The global pipe runs `transform` plus
   `enableImplicitConversion`, so class-transformer read `design:type` as `Array`, had no element type, and
   rebuilt every element as `new Array()`. Count preserved, contents destroyed. Every LoA template in prod
   was stored as `[[],[],...]`. Sibling `Record<string, unknown>` fields survived because their design:type
   is `Object`, which is why `layoutConfig` was fine.
2. **`submit()` never stamped `submittedAt`.** The field was `readonly`, so the domain method could not set
   it; the mapper persisted `undefined`. Only the portal self-submit path stamped it, via raw Prisma. Any
   admin/manual submit left `submission_date` NULL, and `LoaEligibilityService` returns ineligible on a null
   `submittedAt` before it checks the batch. 101 rows affected. Re-releasing the batch could never help.
3. **`{{institution}}` read a dead column.** `participants.institution`, `.nationality`, `.major`,
   `.occupation` are empty for all 13,199 participants. Real values live in
   `participant_applications.personal_data`.

**Why it hid for weeks:** the admin preview posts a hardcoded client-side token constant and a fake
fully-populated sample participant, and renders live editor state rather than the saved row. It never read
the corrupted column and never touched real data. It was structurally incapable of failing the way the
download failed.

## Production changes already applied (irreversible, done by hand)

- Backfilled 101 NULL `submission_date` rows on CYS 2026 from `created_at`. **Eligible went 106 to 207.**
  Rollback list of the 101 ids saved to the session scratchpad (`loa-backfill-rollback.csv`); all were NULL
  before, so rollback is setting them back to NULL.
- Repaired the corrupted `placeholders` JSON on both active `letter_of_acceptance` templates, writing the
  correct 23-token array.
- Verified by rendering a real letter through the prod file service: A4 (595.28 x 841.89 pt), zero leftover
  tokens, correct name/institution/location/dates.

Decisions taken: backfill used `created_at` rather than `paid_at`, because Aldi's stated intent was
"registrants from 1 April to 20 July" and one participant paid on Jul 23 (outside the window). Paid-but-still-draft
applications (4 of them) were deliberately left alone.

## Gotcha worth remembering

`@Transform(({ value }) => value)` does NOT stop the array shredding. By the time the Transform callback
runs, class-transformer's implicit `design:type` conversion has already corrupted `value`. The working
passthrough reads the raw `obj[key]` instead. A first attempt at the DTO sweep shipped the broken version
and its own tests caught it (12 of 20 failing).
