## Things a fresh session would otherwise rediscover the hard way

- **`npx jest | tail` returns *tail's* exit code, not jest's.** Exit 0 from that pipeline proves
  nothing. Read the `Test Suites:` line.
- **A regression proof only counts if the file still compiles.** An injection that breaks parsing
  makes jest collect 0 tests, which proves nothing. Always confirm the test count is unchanged.
- **Never `git stash` in `.wt-copy-phase2`.** It shares a stash stack with other branches and carries
  a foreign `hardening/redact-sensitive-logs` stash. Popping it has destroyed work here once.
- **Prod DB creds:** container `ybb-platform-api-yeghdi-postgres-api-1`, db `ybb_platform_db`, user
  `ybb_api_user` — *not* the `postgres`/`ybb_platform` defaults. Pull from the container env.
- **The recurring defect class, 8 instances so far:** a value is silently lost because one layer does
  not carry what the layer beside it writes. A guard at one layer does not protect the layer above it.
- **Implementer self-reports about their own test coverage are claims, not evidence.** One overstated
  its fixtures. Verify coverage claims against the spec file.
- **`.rejects.toThrow(/some_code/)` can never match** — NestJS puts the code in
  `err.getResponse().code`, not `.message`. This was a defect in the *briefs*; all 8 such assertions
  in the real suite match message text and are sound.
- **`clone-from`'s atomicity has an honest ceiling.** Its tests prove the controller doesn't *defeat*
  the rollback — one transaction for the batch, both copiers on the same `tx`, rejection propagating
  uncaught. They do **not** prove Postgres rolls back; there is zero integration coverage. Don't let
  the green suite be read as verification of the property itself.
